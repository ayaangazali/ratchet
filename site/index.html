A coding agent that never decides it's done. The tests do.

Ratchet is an open-source harness for teams running coding agents. Every candidate patch clears a seven-stage verifier gauntlet before it sticks — so the code that reaches your review is proven, not self-reported.

The problem

Agents grade their own homework

Give an agent a repo and a test command, and eventually it finds the cheapest way to make tests pass: change what "pass" means. It skips the hidden suite, hardcodes the visible cases, edits the tests at import time — then tells you it's done. That's measured behavior, not a hypothetical.

Without Ratchet

"Done" is a belief

The agent declares success, and you find out in review — or in production — that "success" meant a deleted regression test and a special-cased return value.

With Ratchet

"Done" is a verdict

There is no done tool. Green is set in exactly one place — the verifier — after the patch clears build, cheat check, hidden tests, regressions, types, lint, and diff hygiene. Stopping the agent isn't a prompt asking nicely; it's a rollback it can't argue with.

What you get

Six mechanisms, one guarantee

Everything below ships in the repo today, covered by tests, exercised by make proof with no model, no key, and no network.

Verifier gauntlet

Seven stages before green

Every candidate patch is graded against hidden tests it can never read. You stop reviewing patches that only look finished.

Cheat detector

Every known attack blocked

Skip markers, hardcoded answers, spoofed exit codes, conftest report hooks, tests rewritten at import — a published red-team battery scores the verifier itself, in CI, at zero false positives.

Tree search

Dead ends cost a rollback, not a rewrite

Every step is a git commit plus a sandbox snapshot, so a run is a search over repo states. Stalled branches fork in parallel; pruned work is parked, never lost.

Receipts

A tamper-evident chain for every run

Every graded node is signed into a hash chain. Forge a green verdict and make audit says CHAIN BROKEN — you can prove the run is the run that happened.

Human gate

Nothing irreversible without you

The winning path exits as one squashed diff at an approval gate. Pull requests and pushes wait for a human decision, every time.

Docs oracle

Real docs, not model memory

When a failure looks like an API mismatch, current upstream documentation for the exact locked version is attached to the next prompt — so the agent stops guessing.

Who it's for

Built for people who ship agent-written code

For agent builders

Stop babysitting runs

Point Ratchet at a repo and a task file. The scheduler spends compute where the verifier's score says it's worth spending, and you get one clean diff — not a transcript to forensically audit.

For maintainers

Trust the PR, not the agent

Every graded step is receipted into a tamper-evident chain. When a contribution arrives, make audit proves the tests that passed are the tests that ran.

For researchers

A verifier you can attack

The red-team battery is published and scored in CI. Add an attack, add a rule, and measure the search against a linear loop on seeded bugs with make evals.

Fair questions

Before you ask

Can the agent read the hidden tests and game them?
No. Held-out test names never appear in anything the agent can read — not the context assembly, not the observations, not any bus event that could reach a prompt. And a canary task with an impossible test catches stateful answer-smuggling that leaves zero static findings.
What if the agent edits the verifier or the test files?
Protected paths are reverted before grading on every run, with no flag to skip. Writes to graded paths at runtime are their own cheat finding. The exit code is echoed outside the region the agent can influence.
Does it need Docker, a cloud account, or network access?
No. make test, make redteam, and make proof run with no Docker and no network. Sandboxes come from the TrueForge harness when you run live; the documented fallback is plain git worktrees.
Can it push code without a human?
No. Opening a pull request and pushing are gated behind a human approval interrupt. The gate held in every recorded proof run — the turn ends and waits for a decision.
How do I know these claims are real?
Run make proof. It exercises every claim on this page offline and keeps the evidence — 13 checks, from the red-team score to a forged verdict being detected. The dashboard renders the latest proof run.
What about support and code review?
Every change to Ratchet itself goes through a reviewed pull request with Qodo configured deliberately (.pr_agent.toml is committed). Bugs and questions go to GitHub issues.
About

Why Ratchet exists

A ratchet turns one way. So does this: progress that survives verification sticks, and everything else rolls back. Ratchet started as a bet that the missing piece in coding agents isn't a smarter model — it's an honest referee. The harness (TrueForge) owns sandboxes, sessions, and model routing; Ratchet owns the only question that matters: what counts as progress.

Built by Ayaan Gazali. MIT licensed, developed in the open — every design decision is in the repo's README, research digest, and PR trail.
